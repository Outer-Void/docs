## 2. What Outer Void is

Outer Void is a family of developer tools, an AI runtime (BLUX) and standalone products. The constitution
([constitution/](constitution/README.md)) sets three rules:
- **Standalone products stay standalone.** Every product works with BLUX switched off. BLUX is *integrated*,
  *optional* or *excluded* per repository, never required by a product.
- **Each truth has one owner.** The engines (CogA, cA, DAT, LRC, GOD) own their outputs. BLUX System owns execution
  records. VoidForge owns device operations. Roughin and Vigyl own their business data. BLUX and `ax` route and
  ask; they never take that authority.
- **Evidence over claims.** A status comes only from evidence. Checks that the environment blocks are recorded as
  BLOCKED, never PASS.

### Layers

```
 Products      AXIOM Launcher (void.os) ─ bundles ─ VOID.SYS icons, AXIOM Shooter
               VoidForge · Roughin · Vigyl · Resolver (+ website) · Termux Background · bluxai.app
                                     │ optional, by contract only
 Control       ax (axiom): routes each command to its owning engine, or exits 69
 plane         blux10k (environment authority) · JADIS Toolbox (this workstation)
                                     │
 BLUX          blux: Contract v1 + blux-sdk · capability registry and policy · Model API v1
 platform      Hook System v1 (37 events) · direct `blux` CLI and agent loop · training/evals
                    │ subprocess providers                         │ receipts
 Engines       CogA (reasoning) · cA (construct/repair) · DAT       BLUX System (receipts, operation
               (audit verdicts) · LRC (repo creation) · GOD         graph, hash-chained store)
               (discovery)                                          BluxGPT (provider gateway)
                                     │
 Data          blux-ca-dataset · blux-coga-dataset (generated by the pinned engines, locked splits)
 Governance    docs (constitution, matrix, findings) · credits (attribution ledger) · .github profiles
```

### How work flows

1. **Discovery.** GOD finds capabilities declared in `.blux/` folders, validated through blux-sdk.
2. **Routing.** The BLUX runtime routes each request through policy to a subprocess provider, which is the owning
   engine.
3. **Records.** Every operation gets a prefixed ULID and a receipt in BLUX System. Tool calls link to their parent
   model operation; Stage 43 fixed the case where this was missing (F71).
4. **Repair chain.** CogA → cA → DAT → bounded repair. cA cannot certify its own work: DAT gives the verdict.
5. **Models.** Calls go through Model API v1 with four logical models (`blux-main`, `blux-fast`, `blux-reason`,
   `blux-code`) and explicit, degraded fallback. Only the mock provider is exercised today.
6. **Devices.** VoidForge is the only device authority. BLUX and `ax devices` can request read-only diagnostics.
   Every write needs confirmation from the person at the device, and production writes stay locked.

- **Contracts.** Contract v1, Model API v1 and Hook System v1 are all at version 1.0. One schema set and one
  validator (blux-sdk 0.2.0), with typed errors and prefixed ULIDs.
- **Capabilities.** There are 38 capabilities across blux, blux-coga, blux-ca, dat, lrc, god and jadis.toolbox
  ([capability-registry.json](reassessment/capability-registry.json)).
- **Release-candidate checks (Stage 43).** These passed locally:
  - BLUX switched off;
  - discovery through contracts;
  - authority staying with its owners;
  - operation ids and receipts;
  - provider fallback;
  - BLUX running without BLHermes;
  - offline operation;
  - VoidForge refusing destructive requests;
  - cA unable to certify itself;
  - `ax` routing.

  Real devices, real providers and CI are BLOCKED.

## 9. What it takes to release

### Owner actions (Phase 0)
1. Clear the GitHub billing lock (F49). This unblocks every CI gate and the contract checks.
2. Fund at least one model provider (F10). This unblocks BluxGPT, the real `blux` path and the Gen 0 suites.
3. Provide an Android phone, ideally a Pixel and a Samsung. This unblocks VoidForge, the launcher family and
   Termux Background.
4. Fix the Cloudflare custom domain (F54) and verify the tunnel.
5. Confirm with an authenticated check that the six product repositories are private (F7).
6. Remove the stale `blux()` function from `~/.zshrc.local` (F65) and the stale `ANDROID_HOME` lines in `~/.zshrc`.
7. Confirm which tool made the post-freeze commits, so credits can resolve UNR-022 and UNR-021.

### Engineering, in the recommended order
1. **DAT pilot release.** Add DAT target policies (F76), then do a full pilot release: green CI, signed tag, notices,
   ledger entry and matrix change.
2. **Fastest path to revenue.**
   - Roughin: staging with Stripe test mode and real R2, plus PostgreSQL evidence.
   - Vigyl: staging, real notification delivery, accessibility, and PostgreSQL evidence.
3. **Launcher family.**
   - Close the Stage 24 gate: real entitlement, integrity and signature verification (F1, F2, F17), the release
     keystore (F21), the device matrix and the legal review.
   - Then the VOID.SYS icon linter and tests, and the Shooter art and audio pipeline.
   - Then reopen Stage 27.
4. **VoidForge for developer support.** The local confirmation screen first. Then hardware acceptance. Then unlock
   writes one class at a time: safe writes, then sideload, then flashing gated by backups, and root last.

## 10. Governance and process

- **Licensing.** Proprietary by default since 2026-10-25. Earlier copies keep their Apache-2.0 grant. Third-party
  notices and verbatim licence texts are preserved.
- **Credits** ([Outer-Void/credits](https://github.com/Outer-Void/credits)).
  - Attribution is evidence-based and classified.
  - AI assistance is counted from `Co-Authored-By` trailers.
  - Undeclared tooling is recorded as unresolved: UNR-021, and UNR-022 for the nine post-freeze commits.
- **Git.**
  - Every change landed on `main` through gated checks.
  - No history was rewritten and no force push was used.
  - Protected branches were pushed with the owner's bypass.
- **Privacy.**
  - `secret-project` and the owner's real `~/.hermes` are never read.
  - No private data enters datasets, and provider hidden reasoning is never stored.
